# PrivKnife tool audit through spec 115

**Release assessment: hold PDF redaction, OCR and WOFF2 export.** A failed raster redaction can expose the original text in the downloaded PDF. An image that yields no recognized text can produce an invented invoice. The font converter also reports success for a WOFF2 file that the reference decoder rejects. Across the suite, the coverage gate can pass with untested branches, and route-level smoke tests leave important mobile workflows unverified.

**Scope.** This report uses commit `d60ab96b72b18774c97a79fa6db18264fcfeb25d`. Specs 01–29, 31–60 and 103–115 account for 72 tool routes. One of these, Web Vitals (29), intentionally displays a retirement notice. Spec 00 covers the platform, 30 and 91 cover localization, the second 31 and 32 folders cover QA and mobile remediation, 61–90 revisit prior tools, and 92–102 set cross-tool acceptance criteria. Counting these as new tools would duplicate results. The snapshot ends at the regex debugger.

Follow the [remediation roadmap and numbered specifications](specs/SPEC_115_REMEDIATION_ROADMAP.md) to address and verify the findings below.

## Findings and acceptance tests

**Critical · Redacted text survives export when rendering fails (05).** I generated a one-page 200 × 200 pt PDF containing the synthetic word `AUDITMARK`, covered the entire page and requested raster flattening. With no DOM renderer available, the production engine returned a PDF. An independent text reader recovered the word. The same fallback runs on rendering exceptions, and disabling flattening selects the overlay writer directly. The flattening test checks byte count, page count, title and author. It never checks the allegedly removed text. Block sanitized export on rendering failure and verify both a successful export and a forced render failure through the UI. Test that the successful file contains no covered text, annotations or source objects carrying the fixture. [Engine](PrivKnife/src/app/tools/privacy/pdf-redaction/engine.ts) · [Export control](PrivKnife/src/app/tools/privacy/pdf-redaction/pdf-redaction.component.ts)

1. **High · OCR can invent output (47).** The worker calls the same image engine as the component. Its raster recognition path requires the DOM `Image` constructor, which is unavailable in a dedicated worker. When input bytes lack the receipt markers and recognition yields nothing, the engine supplies an ACME receipt for $1,700. Uploading a blank 100 × 100 white PNG and clicking Start OCR Extraction in production Chromium produced the same invoice. The existing “real receipt” test accepts any of three words already in that fallback. Fix worker pixel decoding, remove the fabricated result and test a blank image, an independent image with unique text and a damaged image through upload and export. [Engine](PrivKnife/src/app/tools/documents/local-ocr-text-extractor/engine.ts) · [Test](PrivKnife/src/app/tools/documents/local-ocr-text-extractor/engine.spec.ts)
2. **High · Coverage CI checks file presence.** The manifest accepts a listed component, engine or worker even at zero covered branches. The configured inclusion patterns also omit executable helpers with other names and shared application code. A green run therefore gives insufficient evidence for spec 101. Include all production TypeScript, publish per-file results for all four metrics, and raise per-file thresholds from a recorded baseline. Test the gate with a deliberately untested branch in an already-listed file. [CI command](PrivKnife/package.json) · [Manifest implementation](PrivKnife/qa/coverage-manifest.mjs)
3. **High · A failed PDF worker can move the job onto the UI thread (107).** The cropper catches worker errors and calls the full processing engine directly. A large document can make progress controls and navigation unresponsive precisely when the first attempt has already failed. Terminating the worker on reset also leaves its pending promise unsettled. Return a recoverable worker error and settle cancellation explicitly. Test reset during processing, worker startup failure, and a successful retry with a second document. [Cropper component](PrivKnife/src/app/tools/documents/pdf-cropper-booklet/pdf-cropper-booklet.component.ts)
4. **Medium · A superseded regex job can consume the next job’s time budget (115).** The initial two-date example also remained unevaluated in Chromium until an edit. The initialization test calls `runTest()` itself before asserting the result. After editing the corpus, keyboard activation of the Matches tab and JSON download produced both expected dates. A pointer-driven attempt timed out at that step, so touch export still needs verification. The runner resolves the old caller and replaces the timer while retaining its busy worker. A quick replacement job can time out waiting behind the first. Disposal also discards the pending resolver. Terminate an occupied worker on supersession and settle the old call on disposal. Use a controllable worker double to queue two jobs and assert that the second starts immediately and both promises settle. [Watchdog](PrivKnife/src/app/tools/dev/regex-tester-debugger/worker.ts)
5. **Medium · Shared primitives exist but their behavior is unevenly reused.** Only 48 of 72 route directories reference at least one of the shared button, badge, dropzone, progress or split-preview selectors in component TypeScript or HTML. The OCR template implements its own clickable dropzone, progress display fixed at 100%, and hard-coded English controls. Reuse the shared picker and localized status controls. Test keyboard activation, worker progress and Spanish errors in the same user journey. [OCR template](PrivKnife/src/app/tools/documents/local-ocr-text-extractor/local-ocr-text-extractor.component.html) · [Shared components](PrivKnife/src/app/components)
6. **Medium · Large component classes mix state, rendering and job ownership.** Across the 72 routes, 37 have a component class longer than 300 lines. The cropper has 639 lines, PDF watermarking 628 and the lithophane editor 604. Counts exclude decorator templates and styles. The cropper alone handles page rendering, file ownership, worker messaging, download URLs and form state. Keep the Angular component as the view, expose typed options, progress and actions from a component-scoped signal-based view model, and keep the transformation engine independent of Angular and the DOM. Start with the cropper and watermark tools. Extract shared worker lifecycle code once cancellation contracts agree. Use class size for triage and responsibility boundaries for the split. Thirty-seven tool components construct workers directly. The route file spans 2,153 lines alongside a separate 314-line registry and a static QA manifest. Retain alias and SEO tests while deriving canonical routes and the smoke inventory from the same tool metadata.
7. **Medium · Angular conventions are partly enforced.** Lazy component routes, standalone views, modern template control flow and signal-backed state are present. The source inventory found signal use in 71 of 72 component files, 46 explicit OnPush declarations, and no legacy `*ngIf` or `*ngFor` in tool templates. None of the 72 component files references `FormControl`, `FormGroup` or `FormBuilder`. TypeScript 6 enables strict checking by default here. The app does not explicitly enable Angular's `strictTemplates`, and the OCR options use individual `ngModel` bindings despite the typed-form convention. Enable strict template checks in CI, address diagnostics incrementally, and group multi-field constraints into typed forms when touching those workflows. [Routes](PrivKnife/src/app/app.routes.ts) · [Compiler configuration](PrivKnife/tsconfig.json)

8. **High · WOFF2 export produces an unreadable font (56).** I ran the production engine on `LiberationSans-Regular.ttf` with the basic Latin preset, kerning enabled and layout features retained. It returned success and a 57,509-byte WOFF2. Running `woff2_decompress` on that file exited 1. The writer constructs a custom table stream and calls `pako.deflate`. Replace it with a conforming local WOFF2 encoder and require the independent decoder to reopen the result and preserve expected glyphs. [Writer](PrivKnife/src/app/tools/dev/font-subsetter-converter/engine.ts)

9. **Medium · The production build exceeds the initial JS budget.** The production build succeeds, but the repository budget checker counts 366,850 raw bytes of initial JavaScript against a limit of 200,000. Angular reports 401.80 kB for the entire initial bundle including styles. Inspect eager imports from registry barrels and initial localization resources in the bundle graph, then rerun the raw-JS gate. [Budget checker](PrivKnife/qa/bundle-budget.mjs)

## Edge cases to prioritize after the confirmed defects

| Tool family | Fixture and action | Independent check |
|---|---|---|
| PDF and privacy | Rotate a page, redact near its edge, save and reopen. Try an encrypted or truncated PDF, then a valid one. | Render the affected page and extract its text. Check page order, dimensions, absence of redacted text and successful recovery. |
| Encryption and hashing | Round-trip empty and multi-chunk inputs, change the password, cancel midway, then retry. | Compare recovered bytes with the original and hashes with published vectors. A wrong password must produce no plaintext download. |
| 3D | Exercise min/max dimensions, holes near edges, empty geometry, touch orbit and reset while generating. | Reopen the mesh, check physical dimensions, finite vertices, manifold edges and intended holes. |
| Image, audio and video | Rotate an input, try transparent pixels, a missing codec, a zero-duration clip and consecutive jobs. | Decode the exported file independently and compare dimensions, alpha, duration and the selected interval. |
| Text, tables and generators | Use empty input, quoted delimiters, mixed newlines, combining characters and a second edit during processing. | Parse the export with a second reader and compare semantic values, ordering and the latest requested state. |
| All interactive tools | Open the keyboard, change orientation mid-job, dismiss a dialog and retry with a second file. | Verify focus returns, live status is announced, the action remains reachable, stale results disappear and no private payload leaves the browser. |

## Reproducing the measurements

Use an isolated checkout of the revision above, run the commands below from `PrivKnife/`, and point Chrome at the local production preview. The audit reused the workspace's installed dependencies (Angular 22.2.2, TypeScript 6.0.3, Node 26.12.0, Chromium 155). The QA manifest test reconciles 71 active routes against lazy routes in source. Add `/tools/web-vitals` to include the retirement page.

```sh
npm run qa:test
npm run build
npm run qa:bundle-budget
npm run test:ci
npm run qa:secure-preview -- --port 48215
```

The following command exposed a limitation of the smoke harness at phone widths.

```sh
node qa/smoke.mjs --base-url http://127.0.0.1:48215 --route grid-paper \
  --language en --width 320 --require-heading --click-text 'Download PDF' \
  --artifact-extension pdf
```

The single-click harness selected a hidden Download PDF button and failed. Following the actual 320-pixel workflow, **Page Preview → Download PDF**, produced a 108,151-byte PDF. Independent inspection reported one A4 page. Add a multi-step interaction to the smoke test before classifying that route as a failed export.

The narrow-screen survey used touch-enabled 320 × 844 and 390 × 844 viewports. For each canonical route it loaded the page, waited for an H1, recorded uncaught page errors, and compared `document.documentElement.scrollWidth` with `clientWidth`. It counted rendered native buttons with either bounding-box dimension below spec 96's 44 CSS pixels. A small button is a candidate for touch testing, including any hit area provided by a wrapper. At 320 pixels it also clicked the first enabled, visible button with a matching English sample/demo label when available, then remeasured overflow after 800 ms. The two pages shared language storage during the first sweep, so these results establish viewport behavior only. Locale parity, physical-device touch, keyboard and screen-reader acceptance, and full import-to-export workflows for every format remain open.

## Phone usability

All 72 routes rendered a heading at both widths after follow-up checks. **16 routes overflowed at 320 pixels and seven at 390 pixels.** The 23 overflowing views included the formatter, regex debugger and several PDF editors. At 320 pixels the formatter added 173 pixels of scrollable width. Fix the editor and action-row layouts first, constrain wide tables or code to a labeled inner scroll region, and verify that the primary action remains reachable after opening the keyboard.

Every route, including the retirement page, rendered at least one native button below 44 × 44 CSS pixels. The count includes the shared navigation. Start there, then check tool-specific controls. Seventeen sample actions were exercised at 320 pixels. Five PDF tools still overflowed after loading the sample. Three-dimensional pages that timed out under load and invoice previews affected by the survey's storage initialization were rerun in isolated browser contexts with a longer wait and guarded frame storage access. All six follow-up observations rendered without an uncaught page error.

## Test reliability and coverage

The production build completed and all 12 QA harness tests passed. The unmodified `npm run test:ci` run failed **66 of 1,988 tests in 27 of 178 files** while the machine also ran a production build and other work. Many failures were 5-second test or 10-second setup timeouts. Two redaction component tests reached a detached ArrayBuffer, and four PDF-to-Word component assertions failed, including heading detection and download creation. A separate production Chromium check uploaded a newly generated PDF at 390 pixels and found its unique text in the Word preview. That browser result supports the simple conversion path. The more demanding component fixtures still need investigation.

Repeating the same test selection with `VITEST_MAX_WORKERS=3` and `--runner-config=audit-vitest.config.mjs` preserved the coverage report on failure. **1,969 passed and 19 failed across 11 files.** The lower concurrency changed which tests failed. The repeat included timeouts in texture processing, 3D generation, audio export and grid paper. Two PDF merger download assertions saw no object URL. PDF repair and Word worker tests also encountered a PDF.js fake-worker module resolution error involving `/pdf.worker.min.mjs`. Investigate worker setup and teardown across suites, and use real browser export checks alongside unit assertions. Preserve both runs when evaluating reliability.

| Branches | 11,058 / 17,888 | 61.81% |

All 182 required files appeared in the repeat report. Only the retired Web Vitals component reached 100% on all four metrics. **24 of the 37 worker files had zero line coverage.** Start there with message-level tests covering valid data, malformed messages, failure, cancellation and cleanup, followed by actual browser worker dispatch. The percentages cover the configured engine, worker, component and registry files. Helpers such as the GIF encoder, metronome and MD5 implementation fall outside that denominator. Specs 101 and 102 still have open acceptance items, and the 59-tool release checklist predates specs 103–115.
