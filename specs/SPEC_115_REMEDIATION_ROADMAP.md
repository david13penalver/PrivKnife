# Spec 115 audit remediation roadmap

Implement Specs 135–146 in numerical order. Close each spec against its acceptance checks and evidence, then use a Conventional Commit before starting the next one.

The audit covered original Specs 01–29, 31–60 and 103–115 at revision `d60ab96b72b18774c97a79fa6db18264fcfeb25d`. The 72 routes comprise 71 active tools and the retired Web Vitals notice. The source folder is used to resolve each audited entry to its current canonical URL. Aliases are additional compatibility checks. Specs 116 onward remain in application-wide regression gates. [Historical audit](../SPEC_115_TOOL_AUDIT.md)

PDF redaction, OCR and WOFF2 already have applied fixes and recorded targeted verification. The startup limit now requires less than 300,000 raw JavaScript bytes. Spec 136 preserves those results and extends the evidence where required. The audit identified physical-device touch, assistive workflows and broader formats and routes as open verification work. Each new specification starts pending. [Priority-fix verification](../SPEC_115_RECOMMENDED_SKILLS.md#verification-of-the-priority-fixes) · [Bundle policy](../AGENTS.md)

Use synthetic fixtures for private inputs. Inspect secure-preview network activity for every import-to-output case. Keep partial, blocked and unexecuted cases visible so they can be closed against the same criteria.
